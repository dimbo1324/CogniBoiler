# AI Assistant Rule Modules

Single source of truth for the rules that govern every AI assistant (Claude Code, Codex,
and any future agent) working in this repository.

## How it works

```text
.ai/universal/*.md   Portable rules. Valid for ANY project. Never mention project names,
                     paths, or stack specifics.
.ai/project/*.md     Rules specific to THIS project: repository map, commands, domain
                     guardrails, progress tracking, command reference.
CLAUDE.md            Thin entry point for Claude Code. Imports every module via native
                     @path syntax.
AGENTS.md            Entry point for Codex. GENERATED by concatenating the same modules
                     (Codex has no import mechanism). Never edit by hand.
.ai/CHANGELOG.md     History of rule changes: what changed, why, and when.
```

Modules load in filename order: `universal/01..NN` first, then `project/10..NN`. Later
content overrides earlier content, so project rules win over universal rules when they
conflict (for example, a stricter file-size limit).

## Editing rules

1. Edit or add a module under `.ai/universal/` or `.ai/project/`.
2. Record the change in `.ai/CHANGELOG.md`.
3. Regenerate the Codex entry point: `python dev_tools_scripts_runner.py sync-agents`.
4. Commit the module, the changelog entry, and the regenerated `AGENTS.md` together.

Never edit `AGENTS.md` directly — it carries a generated-file banner and any manual edit
is lost on the next sync; the quality gate fails while it is out of sync. `CLAUDE.md`
needs no regeneration: Claude Code resolves `@` imports at session start.

The full protocol for changing rules — when it is allowed, who decides, how conflicts are
resolved — lives in `universal/08-rules-evolution.md`. Read it before touching a module.

## Size budget and module tiers

Codex reads at most 32 KiB of project instructions. `sync-agents` fails if the assembled
`AGENTS.md` exceeds 30 KiB.

- **inline** (default) — the module is embedded in `AGENTS.md` in full.
- **extended** — only the module's title, path and a one-line essence are embedded. Opt in
  with `<!-- tier: extended -->` in the first five lines, and put
  `> **Essence.** One sentence covering the module's core rules.` right after the title.

Inline is what an agent must know before reading anything else: orientation, process,
constraints that prevent irreversible harm. Extended is refinement read when a task
touches it — and it binds exactly like inline. `CLAUDE.md` imports every module
regardless of tier.
