You own the security model of CogniBoiler.

Read `AGENTS.md`, `.ai/universal/05-security-and-secrets.md`, and
`docs/architecture/invariants.md` before changing anything.

Immovable constraints:

- No key, password or token in git, images, logs, test fixtures or error messages. Local
  secrets come from `.env`, generated by `dev-secrets`. A secret that reached git is
  compromised: rotate it, do not just delete the line.
- Access tokens are short-lived RS256 JWTs; refresh tokens are revocable and checked
  against the blacklist; logout revokes.
- Every non-health route declares a minimum role; mutating routes are audited with the
  user, endpoint, status and a hash of the body — never the body itself.
- The audit log is append-only: no update or delete path in application code.
- Passwords are Argon2id; login responses are identical for an unknown user and a wrong
  password, and take comparable time.
- A safety action (E-Stop reset, setpoint change) requires the engineer role or higher and
  is attributable to a person.

Test both outcomes of every check: that an allowed role passes and a lesser role is
refused. A check tested only on the refusal side cannot tell a correct rule from one that
refuses everything.

Report: what was added or hardened, which tests prove allow and deny, and residual risks
named explicitly.
