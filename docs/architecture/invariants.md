# Invariants: what must never break

> This registry is binding. Breaking an invariant is a defect, not a trade-off. Only the
> owner can change one, and that decision is recorded — with its date and reasoning — in the
> project's decision log. Each entry says honestly how it is enforced today.

## I1. The physics engine is the single owner of process state

Only `physics-engine` advances the plant model and holds the authoritative state. Every
other service observes it through `PhysicsService` or MQTT and never keeps a competing copy
that it treats as truth.

**Why.** Two writers of one plant produce states no real plant can reach, and every trend,
alarm and audit entry downstream becomes untrustworthy.

**Enforced by.** Service boundaries and review (`docs/architecture/service-boundaries.md`).

## I2. Actuators are reached only through the PLC

Every valve command from a person, a script or a future AI component goes through
`PLCService`, which validates it, applies the interlocks and refuses it while an E-Stop is
latched. The gateway never calls `PhysicsService.ApplyControlCommand`.

**Why.** It is what makes the safety layer mean anything: a second path to the actuators is
a path around the interlocks.

**Enforced by.** The gateway only holds a PLC command client; review of any new client of
`ApplyControlCommand`.

## I3. Interlocks and the E-Stop latch cannot be disabled

No configuration value, API parameter, environment variable or flag turns an interlock off.
Resetting a trip is an explicit action by an engineer or admin, recorded in the audit log.

**Why.** A safety function that can be switched off will be, the first time it is
inconvenient in a demo.

**Enforced by.** Interlock thresholds are code constants covered by tests; the reset route
requires the engineer role; the PLC refuses a reset while the trip cause is still present,
and refuses commands that claim the PID or SAFETY source, so no caller can pass for the
interlock.

## I4. SI units and UTC epoch milliseconds in every contract

Protobuf messages, MQTT payloads, REST bodies, database columns and InfluxDB fields carry SI
values with the unit in the name (`pressure_pa`, `steam_temp_k`) and times as UTC epoch
milliseconds (`timestamp_ms`). Conversion to bar, °C or MW happens only at a presentation
edge.

**Why.** A unit mismatch across a service boundary is silent: the number is plausible and
wrong.

**Enforced by.** Naming convention and review; unit conversion is confined to presentation
code.

## I5. No secret is ever committed

Passwords, tokens and private keys live in `.env` (generated by `dev-secrets`), the
environment, or CI secrets. The repository holds only `.env.example`. A secret that reached
git is rotated, not merely deleted.

**Why.** Git history is permanent and public repositories are scraped for keys within
minutes.

**Enforced by.** `.gitignore` (`.env`, `certs/*.pem`, `certs/*.key`) and review. The dev
JWT keys once committed to the `helper` branch are considered compromised and unused.

## I6. Contracts change additively

Protobuf fields are added with new numbers and never renumbered, retyped or reused; MQTT,
REST and WebSocket shapes gain fields rather than lose or rename them unless every consumer
changes in the same task; database schema changes go through Alembic migrations.

**Why.** Services are deployed and restarted independently; a consumer one version behind
must keep working.

**Enforced by.** `generate-proto --check` in the quality gate keeps stubs and `.proto` in
step; the rest by review (`contract-change` skill).

## I7. AI is optional

No service needs `ai-predictor` or any model to start, run, or pass its tests. AI components
may read data and propose actions; executing them still goes through I2.

**Why.** The platform must be complete and demonstrable on its own (owner decision
2026-09-14), and an optional layer must not become a hidden dependency.

**Enforced by.** `apps/ai-predictor` is not a uv workspace member, so nothing can import it.

## I8. One machine, one command, no internet

The whole platform starts with `python dev_tools_scripts_runner.py stack up` on one machine
and runs without internet access once images are built.

**Why.** A portfolio demo that depends on cloud services or manual setup fails at the worst
moment.

**Enforced by.** Docker Compose with pinned images and provisioning from the repository.

## I9. Unit tests need no infrastructure

Tests under `apps/*/tests` run without a broker, database, network or real time: fakes,
SQLite in memory, and in-process gRPC servers on port 0.

**Why.** A test suite that needs a running stack is not run, and a test that depends on
machine speed is not trusted.

**Enforced by.** The quality gate runs the suites without starting any service. The plant
is a deterministic simulator that tests can step directly; the AUTO hold test steps it in
lockstep with the PLC scan, and the remaining PLC integration tests still run it in-process
against the wall clock at high speed, which is the remaining gap to close (debt Д2).

## I10. The audit log is append-only

Rows of `audit_log` are inserted and never changed or removed: no service, script or
migration updates, deletes or truncates them, and the database refuses such statements.

**Why.** An audit trail that can be edited answers nothing: the one record of who moved a
valve, who reset a trip and who was refused must be the record that was written.

**Enforced by.** Triggers created in migration `0003_sessions_and_append_only_audit` raise
on `UPDATE`, `DELETE` and, on PostgreSQL, `TRUNCATE`; the gateway only inserts, and a failed
insert is logged with the whole record instead of being dropped. The gateway connects as
`cogniboiler_gateway` (migration `0004_application_roles`), which may only `SELECT` and
`INSERT` on `audit_log` and owns no table, so it can neither change a row nor disable the
triggers; only the migration job connects as the owner.

## I11. Every write from a protocol edge goes through the gateway

A client of an edge protocol — today OPC UA, tomorrow anything else — never commands
`PLCService`, `AlarmService` or `PhysicsService` on its own behalf. The edge signs its user
in at the API gateway and calls the same REST routes a person's console would, so the role
check, the audit row and the command path are identical.

**Why.** A second write path is a second authorization model, and the first one to be
forgotten. Reads may be projected freely; actions must be attributable to a person the
gateway knows.

**Enforced by.** `opcua-server` holds no command client: its gRPC clients only read status
and alarms, and its methods call the gateway with the session user's token (decision
2026-09-16). Any new edge service is reviewed against this entry before it gains a write
path.
